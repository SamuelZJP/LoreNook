# 后端问题记录

记录测试中确认的后端问题、预期行为与实施结果。

## BE-001 归档生成结果的有效性校验

- 记录日期：2026-10-20
- 状态：已实现（2026-10-20）。
- 涉及模块：状态更新、回合摘要、情节摘要。

### 问题

模型可能返回结构正确但内容无效的结果。仅通过响应结构、非空文本及状态 Schema 校验，不能识别摘要内容显著偏少或状态完全未更新的情况。

### 预期行为

1. 回合摘要结果显著偏少时，视为回合摘要失败。
2. 情节摘要结果显著偏少时，视为情节摘要失败。
3. 状态更新完成 Patch 应用及 Schema 校验修正后，若最终状态与更新前状态完全相同，视为状态更新失败。判断依据是最终状态内容，不只是 Patch 是否为空或是否包含操作。
4. 上述结果不作为成功产物保存，不推进对应归档步骤，进入现有失败与重试流程；此前已完成步骤的结果保留。

### 已实施规则与依据

- 有效字数按 Unicode 文字和数字（`str.isalnum`）计数，不计空白、标点和符号。输出中的独立日期地点头不计正文，情节标题亦不计。独立头的识别为首行以数字年份加 `-`、`/` 或 `年` 开始，或以 `年月日`、`起始时间`、`yyyy` 格式占位文字开始，并包含 `—`；整行排除，只有头时有效正文为零。保持返回原文，不改写或截断。
- 回合摘要最低为 `min(75, max(1, ceil(N / 5)))`；N 仅计本回合用户输入及 AI `<content>` 正文。状态、历史摘要及提示词不计。
- 情节摘要最低为 `min(100, max(1, ceil(N / 5)))`；N 累计选定范围的用户输入与 AI 正文，以及实际提供的首条消息（有标签时仅正文）。状态、回合摘要、桥接回合和范围外材料不计。
- 75、100 分别是现有提示词约150字、约200~300字目标下沿的一半，作为显著不足的保守下限；20%输入比例避免短对话被迫凑字。下限封顶，不随长情节线性增长，也不设输出上限。实施时只读抽查当前库最近30回合：用户输入41~115字符、AI正文745~1978字符、回合摘要133~279字符；两条情节摘要248、324字符（此处为含标点的原始字符统计）。样本用于核对量级，阈值主要依据提示词目标，不以当前样本最短值划线。
- 状态在 Patch 应用、Schema 修正和统一世界字段校验完成后比较完整 JSON；对象键顺序无关，值类型和数组顺序有区别。空 Patch、全部跳过、写回原值、操作抵消、修正恢复原值均由最终结果判定。
- 过短摘要和最终未变化状态均返回422，复用原有错误记录、调用日志和重试；不保存无效成功产物，不推进失败步骤，保留已完成步骤及情节范围。原始模型响应仍保留在既有调用日志中。
- 提示词说明最低有效字数与短输入据实简写；状态提示词明确空 Patch 不能作为成功更新，确实无变化时如实说明并交由系统记错，禁止为了通过检查编造时间、地点或其他变化。
- 新规则只用于正在执行的归档生成，不追溯校验历史记录、导入或手动编辑。成功归档后重新生成摘要或情节仍不实现。

2026-10-20 补充实施：两类摘要长度检查通过后，去除首尾空白并检查开头是否匹配 `[0-9]{2}`，仅接受 ASCII 数字。回合摘要检查完整文本，情节摘要检查解析后的 `summary` 字段，不检查标题或 JSON 包装；不扩展为完整日期校验。失败返回422，复用现有记录与重试，保留此前结果及步骤，成功仍保存原文。提示词及中英文模块文档已同步。

### 验证

补充测试覆盖介绍语、标签、围栏、单个数字、全角和阿拉伯文数字开场失败；有效数字开场与首尾空白保留、失败后重试清错，以及情节标题数字和外层 JSON 围栏不影响字段检查。

- 新增两类摘要阈值前一字失败、恰好达到下限成功、失败后重试及既有结果保留测试；计数覆盖标点、空白、符号、独立场景头和短输入下限。
- 状态覆盖空 Patch、全部跳过、写回原值、Schema 修正恢复、操作抵消、对象键重排失败后重试，以及数值/布尔类型、整数/浮点类型、嵌套值和数组顺序变化正常推进。
- 完整归档测试覆盖三种无效结果均停在各自步骤，重试跳过已完成步骤并最终完成，情节判定与覆盖规则保持原行为。
- 输入计数测试验证状态、重复摘要、正文外报告与桥接回合不抬高下限，实际提供的首条消息参与计数；调用日志验证 HTTP 正常但内容无效时记录步骤失败，重试递增尝试次数并清错。
- 验证结果（含数字开头规则）：`.venv\Scripts\python.exe -m pytest -q --basetemp=.pytest_be001_prefix_final --tb=short`，666 项全部通过（56.71秒）；本次修改的已跟踪文件通过 `git diff --check`。测试使用临时数据库和模拟模型传输。

### 验收要点

- 结构合法但显著过短的两种摘要均失败，保留在各自原步骤并可重试。
- 空 Patch、写回原值的 Patch，以及经 Schema 修正后恢复原值的结果，只要最终状态完全不变，均失败。
- 最终状态确有变化且通过既有校验时，可以正常保存并推进。
- 有效摘要可以正常保存并推进；不改变情节判定与覆盖范围规则。
