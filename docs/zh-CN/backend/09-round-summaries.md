# LoreNook 回合摘要模块

[English](../../backend/09-round-summaries.md) | [中文文档索引](../index.md)

更新日期：2026-10-19

## 1. 职责与实现

状态更新成功后，回合摘要模块根据本回合已确认的用户输入、AI 正文和更新后状态，概括关键事件、人物互动及重要事实。摘要保存成功后推进到情节判定，不在本阶段执行情节判定或生成。

| 文件 | 职责 |
| --- | --- |
| `modules/round_summary/prompts.py` | 内置摘要提示词与材料分节 |
| `modules/round_summary/generate.py` | 请求构造与摘要响应校验 |
| `modules/round_summary/service.py` | 摘要读取及最新已归档回合的手动编辑 |
| `workflows/round_summary.py` | 输入快照、事务外生成、结果保存、失败与重试 |
| `schemas/round_summary.py` | 输入快照、结果、读取与编辑契约 |
| `api/round_summary.py` | HTTP 入口 |
| `llm/generation.py`、`llm/text.py` | 与状态模块共用的原生请求构建与可见文本提取 |

模块使用现有 `rounds.summary`、状态快照和模型配置，无新增表、迁移或依赖。生成不执行写作预设或定义模板，也不改变已保存正文、状态与情节。完整流程由[确认归档](12-archiving-workflow.md)串联；当前入口处理已经保存且处于 `round_summary` 步骤的回合。

## 2. 输入与前置条件

在同一个读事务中收集：

- 当前聊天内角色与用户身份名称。
- 最新回合，要求 `archive_step=round_summary`，且尚无已保存摘要。
- 该回合已确认的用户输入与完整 AI 输出。
- 通过 `Repository.state_for_round(chat_id, round_id)` 精确读取的本回合状态，角色归属必须一致。
- 当前聊天的 `round_summary` 模型用途绑定及连接配置。
- 本回合之前最近若干个已归档回合的摘要，按回合序号排列。

必须使用本回合已经更新并保存的状态；缺失时返回冲突，不回退到初始状态或上一回合。此处只读取状态，不重新执行 Schema。角色或身份名称帮助识别本回合人物，已解析定义与 First Message 不进入摘要材料。

上下文默认包含最近 3 个已归档回合摘要，通过 `Settings.round_summary_recent_summaries` 调整。非正数表示不提供最近摘要。查询复用 `Repository.summaries_before`，不包含本回合，不屏蔽情节已覆盖回合；历史摘要只帮助理解衔接，不作为重复归纳旧事件的依据。

AI 输出只提供唯一、闭合且非空白的 `<content>` 内部原文，用户输入另行提供。报告、其他标签及完整 AI 输出中正文之外的内容不进入提示词；数据库原文不修改。

## 3. 内置生成与结果校验

`modules/round_summary/prompts.py` 定义内置提示词；生成器使用“上下文 → 当前状态 → 最近回合摘要 → 待摘要内容 → 任务 → 摘要格式”的结构。上下文明确主角、“我”和用户角色的实际名称。

当前状态使用本回合已更新并保存的完整 YAML；最近摘要仅帮助衔接，不重复归纳。待摘要内容为当前用户输入与 `<content>` 正文，保留关键对白、情报、行为、情感和状态变化，区分计划、猜测与既成事实。

输出格式要求：

```text
年月日—时分—地点
约150字的第三人称事实摘要
```

日期、时间、地点依据当前状态，缺失时不编造。直接呈现事实，不加解读、评价、推测、预演或结尾总结，不输出标签、JSON、工具调用或代码围栏。字数和场景行由提示词约束，不用机械正则改写或截断模型输出；运行时要求正常完成的单个非空文本回复，首尾空白和换行原样保存。

支持 `google_generate_content`（单候选、`text/plain`）和 `deepseek_chat_completions`（系统、用户消息，非流式、文本模式）。默认参数由模型配置补齐。可见文本提取器拒绝工具调用、显式拒绝和截断结果，原生思考仅保留在完整调用日志中。见[模型调用](06-model-calls.md)。

## 4. 保存、错误与重试

生成期间不持有数据库事务。成功后开启短写事务，重新核对当前回合、步骤、正文、本回合状态、角色/身份名称、历史摘要及模型配置。输入发生变化时返回 409，不保存过期结果；整数与布尔值等 JSON 类型变化也会被识别。

输入一致时调用 `ArchiveRepository.save_summary`，在同一事务中保存非空摘要、清空旧错误，并推进到 `episode_decision`。保存或提交失败则整体回滚，不留下只保存摘要而未推进的结果。

正文、模型调用或响应解析失败时，另开短写事务，在核对输入和步骤后仅记录当前步骤错误，再返回原错误。状态更新结果和正文保持原值，仍停留在 `round_summary`。若期间已有其他请求成功推进，不覆盖成功结果或其错误字段。

重试使用同一个生成入口，只重新执行回合摘要，不重复状态更新或创建回合。成功步骤不能再次生成；即使摘要已经保存，尚未完成情节判定等后续步骤时仍不能发送下一回合。

## 5. HTTP 接口

集合前缀为 `/api/chats/{chat_id}/rounds/{round_id}`：

| 方法与后缀 | 行为 |
| --- | --- |
| `POST /round-summary` | 使用数据库材料生成，成功保存并推进到情节判定 |
| `GET /summary` | 读取该回合已保存的摘要，可读取历史回合或尚未完成后续归档步骤的摘要 |
| `PUT /summary` | 整体替换最新已完成归档回合的摘要 |

生成不要求请求体，不使用客户端提供的替代状态或模型输出。成功返回：

```json
{
  "chat_id": "聊天ID",
  "round_id": "回合ID",
  "summary": "摘要原文",
  "archive_step": "episode_decision"
}
```

读取与编辑返回 `chat_id`、`round_id`、`summary`。编辑请求为 `{"summary": "非空白文本"}`，不接受 `null`、错误类型或额外字段。编辑仅改变摘要，不触发模型、状态重算或情节重算；归档过程中及该回合不再是最新回合时禁止编辑。没有已保存摘要时，读取返回 409。

- 404：聊天或回合不存在，或回合不属于当前聊天。
- 409：目标非最新回合、步骤不符、摘要已存在但步骤未推进、缺少必要资料/本回合状态/模型绑定、输入过期，或编辑范围不符。
- 422：编辑字段、AI 正文、模型配置或摘要响应无效。
- 502/504：沿用模型调用的上游错误与超时映射，不回显 Key 和上游错误正文。

## 6. 验证

使用实际临时数据库、迁移和 HTTPX MockTransport，不访问真实模型。

覆盖本回合状态精确读取、日期时间地点、正文区段隔离、角色身份、默认参数合并、非空文本与原文保留、原生思考过滤、无效候选/工具/截断响应、调用与正文失败、重试清错、只修改摘要与步骤、重复生成拒绝、范围隔离、状态类型变化与其他过期输入、并发失败不覆盖成功结果、保存回滚、手动编辑范围，以及最近摘要窗口和情节覆盖。

状态更新到回合摘要的串联测试验证使用新状态且不重复执行状态步骤；共享响应提取器的既有状态测试继续通过。
