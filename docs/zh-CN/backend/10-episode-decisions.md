# LoreNook 情节判定模块

## 1. 职责与实现

情节判定在回合摘要保存后执行，决定本次是否需要生成情节，以及需要覆盖的连续回合范围。不调用模型，不分析剧情正文或摘要文本，不生成情节摘要。

| 文件 | 职责 |
| --- | --- |
| `schemas/episode_decision.py` | 候选、日期输入、判定范围与步骤结果契约 |
| `modules/episode_decision/service.py` | 限定归属、步骤检查及输入收集 |
| `modules/episode_decision/dispatcher.py` | 方法选择、候选校验与统一范围构造 |
| `modules/episode_decision/methods/day_boundary.py` | 第一版跨日与回合数判定 |
| `workflows/episode_decision.py` | 同一短事务内计算、保存和推进步骤 |
| `api/episode_decision.py` | HTTP 入口 |

复用现有回合、情节和状态表，无新增迁移或依赖。不依赖写作预设、模型绑定、X/Y 或记忆装配是否已经采用某个情节。

## 2. 候选与日期查询

只允许对当前聊天最新且处于 `episode_decision` 的回合执行判定。候选为所有尚未被已保存情节覆盖的回合，包含当前回合，按回合序号排列；之前的候选必须已完成归档。

已归纳回合完全不进入方法输入：既不是候选，也不提供其状态作为额外上下文。筛选使用情节真实覆盖区间，不以情节是否已被写作请求采用为依据。判定范围已保存但情节尚未生成时，覆盖边界不移动。

判定输入通过以下 Repository 查询组织：

| 查询 | 返回 |
| --- | --- |
| `round_header(chat_id, round_id)` | 限定归属的回合 ID、序号、步骤 |
| `latest_round_header(chat_id)` | 最新回合的同类元数据 |
| `unrepresented_round_headers(chat_id)` | 未被情节覆盖的回合元数据，按序返回 |
| `round_dates(chat_id, round_ids)` | 指定回合状态中 `世界.日期` 的投影，不回退到初始或其他状态 |

方法上下文只包含当前回合 ID、候选 ID/序号，以及候选中最新两回合的日期。候选只有当前回合时不查询日期。查询日期时保留原值类型，缺少快照、缺少字段或字段值不合要求，均不能被猜测为有效日期。

## 3. 第一版规则

内置方法为 `day_boundary`：

1. 暂时排除最新回合。
2. 剩余候选不足 5 个，直接返回“否”，不要求日期有效。
3. 达到门槛后，要求最新回合与上一候选回合的 `世界.日期` 都是严格 `YYYY-MM-DD` 格式的有效日期字符串，并解析为日期值。
4. 两个日期相同，返回“否”。
5. 两个值不同，以上一回合为截止回合，归纳最新回合之前的全部候选；最新回合继续保留。

使用统一的严格日期解析器比较日期值，不接受附带星期、首尾空白或其他格式。日期不同即触发，包含日期向前或向后变化。星期、时间和地点不参与情节判定。达到门槛后日期缺失、格式或日历值无效时判定失败，不以“无需情节”兜底；旧格式需手动修正。

例如候选为 13—20，若符合跨日规则，则覆盖 13—19，留下第 20 回合。候选为 13—17 时，排除最新后只有 4 个，无论是否跨日都不生成情节。

## 4. 方法切换与范围契约

通过代码中的 `dispatcher.DEFAULT_METHOD` 选择方法，`METHODS` 注册同步计算函数。内部调用也可显式传入 `method`；HTTP 请求不提供方法或范围覆盖。

方法接收独立的 `EpisodeDecisionContext` 副本，返回截止回合 ID，或用 `None` 表示“否”。Dispatcher 统一负责：

- 将候选按回合序号排序，检查 ID 无重复、序号连续且包含当前最新回合。
- 需要生成时，起始回合固定为最早候选，截止回合必须属于当前回合之前的候选，范围连续并包含两端。
- 未知方法或不合法截止回合明确失败，不切换兜底方法。

例如其他方法面对候选 13—20 返回第 17 回合，则统一得到 13—17。方法不能通过返回当前回合或候选外 ID 改变范围约定。计算不修改调用方输入，也不向方法提供 Repository、正文或其他历史文本。

## 5. 保存与重试

输入读取、纯计算及 `ArchiveRepository.save_decision` 在一个 `BEGIN IMMEDIATE` 短写事务内完成，无外部模型或网络等待，不需要跨事务的生成结果核对。

- “否”：保存 `episode_required=false`，端点保持为空，清空旧错误并直接推进到 `complete`。
- 需要情节：保存 `episode_required=true` 及起止回合 ID，清空旧错误并推进到 `episode_summary`。
- 方法或必需日期错误：只保存当前步骤错误，仍停留在 `episode_decision`，提交后返回错误。
- 记录不存在、归属/步骤不符或候选结构冲突：返回相应错误，不改变记录。

保存端再次检查范围从最早未归纳回合开始、覆盖连续已归档回合，且在当前回合之前截止。事务提交失败时结果整体回滚；重复请求或并发中的后到请求在步骤检查处被拒绝，不重复计算并覆盖已保存范围。

本步骤不新增 `episodes` 记录。保存范围不意味着回合已经归纳；情节摘要成功保存后边界才移动。后续情节摘要重试应直接使用已经保存的范围，不重新调用本判定接口。

## 6. HTTP 契约

`POST /api/chats/{chat_id}/rounds/{round_id}/episode-decision` 使用数据库输入，不要求请求体。返回：

| 字段 | 含义 |
| --- | --- |
| `chat_id`、`round_id` | 当前聊天及产生本次判定的回合 |
| `episode_required` | 是否需要生成情节 |
| `start_round_id`、`end_round_id` | 选定范围端点；无需情节时为空 |
| `start_round_no`、`end_round_no` | 对应序号；无需情节时为空 |
| `archive_step` | 无需情节时为 `complete`，否则为 `episode_summary` |

- 404：聊天或回合不存在，或回合不属于当前聊天。
- 409：非最新回合、步骤不符、候选不连续/重复/缺少当前回合，或历史候选尚未归档。
- 422：判定方法不存在、截止回合不合法，或达到门槛后所需日期缺失/类型无效。

## 7. 验证

依赖检查通过。覆盖 5 个历史候选的门槛、同日/跨日、严格日历解析比较、缺失与错误日期、低回合数不要求日期、排序与输入隔离、方法切换及非法截止、历史情节屏蔽、下一段从最早未归纳回合开始、范围与步骤保存、失败修复后重试、覆盖边界不提前移动、归属与步骤拒绝、事务回滚及并发仅一次成功。

查询测试验证候选投影不加载正文和摘要，日期读取不包含已覆盖回合；串联测试验证回合摘要后无需额外模型调用即可完成判定。无需情节时可以开始下一回合；需要情节时仍需完成情节摘要。
