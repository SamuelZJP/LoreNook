## 2. 输入材料

使用已保存的连续范围，按回合序号提供每回合的摘要、用户输入、`<content>` 正文和对应结束状态。附带角色名、用户身份名；明确“我”所指的主角。上下文最新状态取范围最后一回合，不读取触发判定的后续回合状态，也不把较晚状态倒用于较早事件。

范围从最早未归纳回合开始，全部来源回合必须已完成归档且具有非空摘要、有效正文与对应角色状态。角色 Schema、定义模板与写作预设不执行；用户输入和正文原样进入材料，报告及正文外标签不进入材料。

- 覆盖从第1回合开始时，提供角色 First Message；后续情节不重复提供。带 `<content>` 时只提供正文，普通文本开场直接使用。
- 允许只读最近一个已保存情节的末回合作为桥接上下文，提供该回合摘要、用户输入及正文。它不重新进入候选，不改变覆盖范围，不重复归纳上一事件。
- 不提供其他已覆盖回合、旧情节全文、范围之后的回合或状态。X/Y 和写作记忆选择不影响本次材料。

Repository 按范围批量读取实际回合与状态，并单独查询最近的桥接回合。保存前重新核对正文、摘要、状态、首条消息和桥接内容，防止生成期间编辑导致过期结果落盘。

## 3. 模型调用与原文

`modules/episode_summary/prompts.py` 按“上下文 → 桥接上下文（如有）→ 事件包含的对话回合 → 任务 → 事件摘要格式 → 输出格式”组织提示词。要求第三人称旁观者叙述，保留关键情节、对白、人物互动、因果和结果，区分计划与事实；不添加评价、推测、预演或结尾总结。

标题不超过20字。摘要以 `起始时间(yyyy/mm/dd)-终止时间(yyyy/mm/dd)—地点` 开头，随后用约200~300字的一段话概括所选事件；只记录状态支持的日期、时间和地点，缺失信息不编造。边界附近属于下一事件的内容不写入当前事件摘要；桥接内容只用于理解当前事件的衔接。

读取 `episode_summary` 模型绑定，使用 Google 单候选 `responseMimeType=application/json` 或 DeepSeek 非流式 `response_format={"type":"json_object"}`。默认参数由模型配置补齐。要求正常完成的单个文本候选，拒绝工具调用、显式拒绝和截断，忽略原生思考。实际完整请求与上游回复先由模型调用层记录。

模型仅输出：

```json
{"title": "事件标题", "summary": "日期范围—地点\n事件摘要内容"}
```

运行时要求恰好两个字段，均为非空字符串，标题最多20个字符。拒绝重复字段、额外字段、错误类型、多对象、非有限数值与非法Unicode；兼容整个JSON外的一层代码围栏，不从混杂说明中猜测截取对象。JSON解析后分别保存标题与摘要字符串，保留字段值的空白和换行。解析失败保留原始日志，停在当前步骤，不以纯文本或旧摘要兜底。

生成摘要正文最低有效字数为 `min(100, max(1, ceil(N / 5)))`，计数采用[回合摘要规则](09-round-summaries.md)。N 累计选定范围内用户输入、提取的 AI 正文，以及实际提供的首条消息（带标签时只计正文）；不计状态、回合摘要、桥接内容及范围外材料。输出标题与独立日期地点头不计正文。100 字取约200~300字目标下沿的一半，结合输入20%规则，拦截显著不足并允许短输入据实简写；不要求编造凑字，不设上限，不改写内容。过短返回 422，沿用现有错误记录和固定范围重试，保留此前结果，不新增情节或移动覆盖边界。不追溯校验历史情节、导入或手动编辑。

JSON解析与长度检查通过后，`summary` 字段去除首尾空白后必须以两位 ASCII 数字（`[0-9]{2}`）开头；标题和 JSON 包装不参与该检查。仅检查前缀，不验证完整日期；保存字段原文。失败返回422并沿用现有错误与固定范围重试，保留此前结果和覆盖边界。提示词同步要求以数字日期起笔，历史记录、导入与手动编辑不受影响。

## 4. 保存、失败与并发

只允许处理当前聊天最新且处于 `episode_summary` 的回合。保存的判定必须要求生成情节，且该产生回合尚无情节结果。

1. 在读事务中收集独立材料和模型配置，关闭事务。
2. 在事务外调用模型。
3. 开启短写事务，重新收集并核对范围、来源正文和摘要、状态、首条消息、桥接内容、角色与身份名及模型配置。
4. 输入一致时，使用已保存的起止 ID 新增情节，记录产生回合，并将该回合推进到 `complete`、清空错误。保存端再次校验连续范围和覆盖边界。

生成失败时同样核对输入，仅更新当前步骤的 `archive_error`，保留步骤和原范围。失败或事务回滚均不新增情节，覆盖边界不移动；修复后重试直接使用原范围。成功保存后，覆盖回合才从下一次情节候选中排除。

输入或步骤在模型调用期间改变时返回冲突，过期结果和错误均不写入。并发请求中已有请求成功保存时，后到结果不能覆盖其情节或错误状态。重复调用成功步骤返回冲突。

## 5. HTTP 契约

| 接口 | 行为 |
| --- | --- |
| `POST /api/chats/{chat_id}/rounds/{round_id}/episode-summary` | 无需请求体；生成并保存，返回 `chat_id`、`round_id`、`archive_step=complete` 和 `episode` |
| `GET /api/chats/{chat_id}/episodes` | 按覆盖起始回合排序返回情节 |
| `GET /api/chats/{chat_id}/episodes/{episode_id}` | 读取指定情节 |
| `PUT /api/chats/{chat_id}/episodes/{episode_id}` | 请求体为 `{"summary":"情节摘要原文","title":"可选的新标题"}`，省略标题则保留原值，立即保存并返回情节 |

情节字段为 `id`、`chat_id`、`start_round_id`、`end_round_id`、`title`、`summary`、`created_by_round_id` 和 `created_at`。所有入口限定聊天归属。

导入的历史情节可将 `created_by_round_id` 设为空，正常读取并参与记忆组装和覆盖计算，通过数据管理编辑。正常生成始终记录产生回合。

编辑仅允许修改最新已归档回合产生的情节标题与摘要，不能修改范围或产生回合，不触发重新生成。下一回合一经保存，上一回合产生的情节即不可在此入口编辑。

- 404：记录不存在或归属不符。
- 409：步骤、范围、来源状态或配置缺失；输入已改变；目标情节不可编辑。
- 422：请求内容无效、接口类型不支持或摘要响应无效。
- 502 / 504：上游调用失败 / 超时。错误不包含密钥或上游响应正文。

## 6. 验证

验证覆盖材料按序与范围隔离、正文与报告分离、首条消息仅进入首个情节、上一情节末回合的只读桥接、标题和摘要JSON校验、字段原文保存、两种接口的JSON输出模式、解析失败与固定范围重试、正文/开场/桥接输入变化拒绝、事务回滚、标题编辑与记忆装配，以及旧数据库升级时保留原始历史。

串联测试验证回合摘要 → 情节判定 → 情节摘要共调用两次模型；情节保存前无法开始下一回合，保存后可以继续。完整串联入口见[归档流程](12-archiving-workflow.md)。
