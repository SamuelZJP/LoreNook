更新日期：2026-10-19

## 1. 职责与实现

写作 Workflow 完成一次发送或归档前的重新生成：读取聊天材料与配置，解析定义，执行预设包装，调用一次模型，再用预设解析响应，返回待确认的完整 AI 输出。

| 文件 | 职责 |
| --- | --- |
| `workflows/writing_materials.py` | 预览与生成共用的聊天快照收集、材料解析 |
| `workflows/preview_writing.py` | 包装请求预览，不调用模型 |
| `workflows/writing.py` | 材料、包装、调用、解析的完整编排 |
| `schemas/writing.py` | 发送输入与待确认结果契约 |
| `api/writing.py` | 聊天写作入口 |
| `api/dependencies.py` | 数据库与模型客户端依赖 |

Workflow 不保存待确认回合，不维护服务器端候选缓存，不执行状态更新、摘要或情节归档。成功代表回复通过本次预设校验；正文正式落盘由[确认归档流程](12-archiving-workflow.md)负责。无数据库结构变更。

## 2. HTTP 契约

`POST /api/chats/{chat_id}/writing` 接收：

```json
{"user_input": "本次用户输入"}
```

输入必须是字符串，保留空白、换行和文本原样。请求不能覆盖定义、状态、历史、预设、模型配置，也不能指定要修改的已保存回合或直接提交替代 AI 输出。

成功返回 200：

| 字段 | 含义 |
| --- | --- |
| `chat_id` | 本次聊天 |
| `preset_id` | 本次使用的聊天内预设 |
| `model_config_id` | 本次使用的聊天内 `writing` 模型配置 |
| `state_snapshot_id` | 材料所依据的状态快照 |
| `based_on_round_id` | 收集材料时最新的已归档回合；首回合前为空 |
| `status` | 固定为 `awaiting_confirmation` |
| `user_input` | 本次输入原文 |
| `ai_output` | 通过预设校验的完整输出，保留返回的标签、空白与换行 |

不返回模型 Key、完整上游响应或中间请求体，也不生成已保存回合 ID。包装请求的查看仍使用 `writing-preview`。

## 3. 执行顺序

1. 开启一个读事务，确认聊天存在，且最新回合已完成归档。
2. 读取聊天当前选用且属于本聊天的预设源码。
3. 读取聊天内角色、身份、First Message、定义、最新状态，以及按 X/Y 装配的历史，转换为独立对象。
4. 在同一个事务中读取 `writing` 用途绑定及其聊天内模型配置，复制地址、Key、模型和默认参数。
5. 关闭数据库会话。
6. 根据这份状态解析所有启用定义，组织材料，包括状态 JSON 与 YAML。
7. 执行预设 `build(materials)`。
8. 由模型调用模块检查接口、合并参数并执行一次 HTTP 请求。
9. 使用同一份源码的 `parse(response)` 提取、校验完整输出。
10. 返回待确认结果。

历史规则沿用[记忆装配](04-memory-assembly.md)，当前输入不计入历史，同一回合只采用一种表示。Workflow 不重排历史、不剥离标签，也不决定 First Message 是否进入实际请求；这些请求转换由预设负责。

只要求当前写作所需的预设和 `writing` 模型配置齐全，不要求提前绑定归档模块的模型。写作模块直接读取已保存状态，不解释或执行角色 Schema；状态生成与校验由[状态模块](08-state-updates.md)负责。

## 4. 快照与事务

资料、定义、历史、状态、预设源码和模型配置在一个读事务中取得。内部快照不携带 ORM Session；定义解析、JavaScript 执行与网络调用均在会话关闭后完成，不持有数据库事务。

本次请求始终使用开始时取得的快照。即使请求期间编辑了预设、状态、定义或模型配置，当前调用仍用原材料包装、原源码解析；下一次请求重新读取新值，不会用旧预设发送、用新预设解析。

`state_snapshot_id` 与 `based_on_round_id` 描述本次生成所依据的历史，不代表服务器保存了候选或锁定了后续归档。确认归档时提交 `user_input`、`ai_output` 与 `based_on_round_id`，入口检查最新回合与前置回合 ID 一致且已完成归档，再保存正文。此检查防止旧候选或重复确认创建下一回合，不作为全部资料的内容版本校验。

预览复用相同的材料收集和定义解析函数，但不要求模型绑定，也不调用模型；新增生成入口不改变预览的原有行为。

## 5. 重新生成与失败

归档前重新生成使用同一入口，再次提交相同输入或编辑后的输入。每次重新读取定义、状态、历史和配置，重新解析并调用模型一次。客户端负责展示或替换候选，旧候选不进入数据库，也不作为重新生成的历史；候选的临时保存与恢复仍不在第一版范围内。

正文已经保存但归档未完成时，`state_update`、`round_summary`、`episode_decision`、`episode_summary` 四个步骤全部阻断写作，包括已经保存状态或摘要的情形。此入口不能重新生成或覆盖已归档回合。

任一阶段失败立即停止，不返回部分 AI 输出，不创建回合，不保存状态、摘要或情节，不修改已有归档错误。模板、包装或配置检查失败时不调用模型；网络或解析失败可重新发送，但不会自动重试或追加调用。

- 404：聊天不存在，或引用记录不属于当前聊天。
- 409：归档未完成、缺少选用预设或 `writing` 模型绑定、必要资料或状态缺失、记忆范围冲突。
- 422：字段、定义模板、预设包装/解析/结果类型、模型接口或请求配置无效。
- 502：上游 HTTP、传输、响应格式或大小等错误。
- 504：模型调用超时。

沿用各模块的错误定位：定义 ID 与行号、预设 `build`/`parse` 阶段、调用错误分类与上游状态码。模型鉴权与上游错误正文不回显。

## 6. 验证

使用实际数据库迁移、Jinja、QuickJS 与 HTTPX MockTransport，不访问真实模型。

覆盖成功生成、编辑后重新生成、失败后重试、定义解析、完整分层记忆、当前输入不计入历史、状态与回合标记、四种归档步骤阻断、资料和配置缺失、各阶段失败、所有表不被写入、Key 不进入结果、示例工具输出往返，以及解析、预设和网络阶段不持有数据库连接。

请求期间修改源码、模型、Key、状态、定义和 First Message 的测试，验证当前请求保持原快照、下一次使用新值。已有预览和模型管理测试继续通过。
