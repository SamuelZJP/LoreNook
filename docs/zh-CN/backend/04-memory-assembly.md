# LoreNook 记忆装配模块

[English](../../backend/04-memory-assembly.md) | [中文文档索引](../index.md)

更新日期：2026-10-19

## 1. 职责与入口

按聊天配置的最近完整回合数 X、最少保留回合摘要数 Y，以及已保存情节范围，选择本次历史表示。每个已归档回合恰好出现一次，结果按回合序号排列，文本保留数据库原文。

| 文件 | 职责 |
| --- | --- |
| `schemas/memory.py` | 已归档回合输入、三种历史表示与装配结果契约 |
| `modules/memory/assembler.py` | 不依赖数据库的 `assemble_memory` 选择函数 |
| `modules/memory/service.py` | 使用 Repository 读取当前聊天并装配 |
| `api/memory.py` | 只读装配预览入口 |

模块不调用模型、不保存或改写记录、不提取 AI 输出标签，也不承担写作预设的请求包装。定义解析、First Message、当前输入和最新状态由写作 Workflow 另行收集。

## 2. 输入与查询

`MemoryService(repository).assemble(chat_id)` 在调用方的同一个读事务内：

1. 读取聊天，取得 `recent_rounds` 和 `min_summaries`。
2. 使用 `Repository.rounds(chat_id, completed_only=True)` 读取已归档回合。
3. 使用 `Repository.episodes(chat_id)` 读取当前聊天的情节；从回合映射取得端点序号，无逐条端点查询。
4. 转换为独立 Pydantic 对象，调用选择函数并返回 `ChatMemory`。

复用既有查询与数据表，无新增迁移。序号决定时间顺序，ID 和创建时间不参与先后判断。

纯选择函数接收 `ArchivedRound` 列表、`EpisodeMemory` 列表及 X、Y。X、Y 必须是非负整数，不接受布尔值、字符串或小数。待发送输入不属于历史，不计入总数 T。

预览排除所有 `archive_step != complete` 的回合，包括已经保存状态或摘要的未完成回合。预览不代表允许发送；写作 Workflow 必须检查当前归档已完成，再收集发送材料。

## 3. 选择规则

1. 将回合按序号排列，最近 `min(T, X)` 个回合使用完整正文，其余暂用回合摘要。
2. 将情节按起始回合排序，从旧到新尝试折叠；一个情节覆盖的回合整体改用该情节摘要。
3. 如果情节触及最近完整回合，或折叠后剩余回合摘要少于 Y，立即停止；不拆分，也不跳过它使用更晚的情节。
4. 按时间顺序输出选中的情节、未被折叠的回合摘要和最近完整回合。

`T <= X` 时只有正文；`X < T <= X + Y` 时只有摘要与正文。没有情节时，正文之前的所有回合继续使用摘要。Y 是折叠约束，历史不足时不凑足；X=0 允许没有完整回合，Y=0 允许把正文之前的摘要全部折叠。

例：T=20、X=5、Y=6，已有情节 1—4、5—8、9—12，选取前两个情节、9—15 的七条摘要和 16—20 的五个完整回合。

若已有范围之间存在未覆盖回合，这些回合继续保留摘要，并在输出中保持实际时间位置，不移动到后续情节之后。正常情节归档仍遵守从最早未归纳回合开始的规则。

## 4. 返回契约

`ChatMemory` 字段：

| 字段 | 含义 |
| --- | --- |
| `chat_id` | 当前聊天 ID |
| `recent_rounds`、`min_summaries` | 本次使用的 X、Y |
| `total_rounds` | 本次已归档回合总数 T |
| `items` | 按时间顺序排列的历史表示，使用 `kind` 区分 |
| `uses_compressed_history` | 本次是否实际使用情节或回合摘要 |

`items` 是带判别字段的联合类型：

| `kind` | 内容 |
| --- | --- |
| `episode` | 情节 `id`、`start_round_id`、`end_round_id`、`start_round_no`、`end_round_no`、`title`、`summary` |
| `summary` | 回合 `id`、`round_no`、`summary` |
| `round` | 回合 `id`、`round_no`、`user_input`、`ai_output` |

每项只携带所采用的表示。例如完整回合项不附带该回合摘要，情节项不附带覆盖回合的正文。

空聊天返回 T=0、空列表和 `uses_compressed_history=false`。标记根据实际选择计算，不根据数据库是否保存摘要或情节判断。预设可用它决定 First Message 是否进入请求；First Message 仍始终由 Workflow 提供，装配模块不删除它。

摘要、用户输入和 AI 输出不做去空白、行结束符转换或标签过滤；空白检查仅用于判定摘要是否有效。返回值不依赖活跃 ORM Session，与输入可变对象断开引用。

## 5. HTTP 与错误

`GET /api/chats/{chat_id}/memory` 使用数据库中的聊天配置进行装配预览，不接收临时 X/Y 覆盖。修改聊天配置后，下次读取立即生效。

- 404：聊天不存在。
- 409：历史存在重复回合、情节端点不属于已归档历史、范围逆序或内部缺失回合、情节范围重叠、情节摘要为空，或本次需要使用的回合摘要缺失。

情节范围在折叠之前完整检查，即使该情节暂未进入本次材料，也不静默忽略错误范围。所需摘要缺失时不自动替换为正文。失败不返回部分装配结果，不修改归档进度。

## 6. 验证

覆盖设计示例、T/X/Y 边界、X/Y 为零、无情节、刚好保留 Y 条摘要、大情节阻止后续折叠、正文边界、不拆分、不重复覆盖、时间排序、未覆盖间隙、非法范围、原文和标签保留、返回对象独立性、聊天隔离、未完成归档排除、配置修改生效，以及 HTTP 404/409。
