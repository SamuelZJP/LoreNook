## [基本定义]

### 预设

**概念**

1. 定义、历史、最近回合、用户输入是请求的基本组成单位，它们需要**转化**为正式请求，这个过程会经历添加系统提示词、改造消息的具体内容等等
2. 接收LLM回复时，LLM的回复可能是需要加工的，需要把回复**转化**为本程序接受的数据格式
3. 上述的两次转化过程，即是"预设"的概念。因此一份预设也许包含：系统提示词、转化过程(可能以过程代码形式体现)、其他内容
4. 写作、摘要、状态更新都需要预设

### 摘要过程

总结回合摘要

### 数据库存储相关

聊天: 类似Chat或者Session的概念，这个对象对应"以某身份和某角色的聊天全程"，因此直接或间接关联下述所有内容
角色: 关联角色姓名、角色头像、元数据描述等等
用户: 关联用户姓名、角色头像、元数据描述等等
定义: 角色定义、用户定义、世界书条目...的统一化概念
情节: 一个情节是若干回合的总摘要，用某种方式总结
回合: 一个回合包含一次用户输入和一次AI输出
状态: 一个回合必定有对应的一个状态，包含时间、地点、人物信息及其他状态等等
摘要: 一个回合的概要性内容

### 发送LLM请求的基本单位

**概念**

定义: 同数据库存储中的描述，在此时将集合在一起，作为一个单独的整体看待
历史: 若干情节和若干摘要按照时间顺序所组成的整体，它们对应的回合内容不会出现在最近回合中，以体现信息压缩的概念
最近回合: 用户输入和AI输出组成的"user-assistant"对，在请求结构中正是user role和assistant role的原始组成部分
用户输入: 用户的最新输入，其实就是最新的user role

## [基本流程]

0. 用户选定或新建chat，在设置里选定写作摘要和
1. 用户输入完毕，点击发送
2. 根据写作预设，将基本单位包装成正式请求体，发送给写作AI
3. 根据写作预设，转化接收到的内容，并将`回合`落盘
4. 用户认可输出，点击归档，后台将回合内容连带所需的上下文同时发送给回合摘要AI和状态更新AI，如果触发了情节归档，则发送给情节摘要AI。
5. 将摘要、状态和可能的情节落盘，同时反馈给用户
